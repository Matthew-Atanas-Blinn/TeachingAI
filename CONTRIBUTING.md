# Contributing to TeachingAI

Thank you for your interest in improving TeachingAI.

The purpose of TeachingAI is to capture durable and reusable knowledge for
AI-assisted curriculum development, instructional design, assessment
creation, grading, autograding, and course improvement.

## Philosophy

TeachingAI is not a collection of prompts.

It is a structured repository of:

- standards;
- review processes;
- source-of-truth documents;
- pedagogical rationale;
- accepted decisions; and
- controlled experiments.

Contributions should improve the system itself, not merely solve an
isolated one-time problem.

The preferred improvement path is:

Problem → Root Cause → Standard → Future Prevention

## Before Contributing

Please read:

- INDEX.md
- META/repository_philosophy.md
- META/repository_rules.md
- META/update_process.md

These documents define repository structure, governance, and change

## Desired Contributions

Examples include:

- new instructional standards;
- improved review checklists;
- pedagogical rationale;
- accessibility improvements;
- privacy and safety improvements;
- repository governance improvements;
- module source-of-truth documents;
- decision records;
- teaching-methodology research summaries;
- validation tooling and automation.

## Contribution Template

When proposing a change, include the following information.

### Problem

What issue exists?

### Proposed Change

What should change?

### Benefits

Why is this improvement valuable?

### Drawbacks

What costs, risks, or tradeoffs exist?

### Assumptions

What assumptions are being made?

### Alternatives Considered

What alternative approaches were evaluated?

### Validation

How was the proposal tested, reviewed, or validated?

### Affected Files

List every file that would be added, modified, moved, renamed, or deleted.

## Repository Governance

All repository modifications must be reported.

Change reports should include:

- files added;
- files modified;
- files moved or renamed;
- files deleted;
- what changed;
- why it changed;
- assumptions;
- validation performed.

No official standard becomes active without approval.

## Experiments

Unapproved ideas belong in:

PROPOSED/

Experimental changes should not alter official standards until they are
accepted.

When an experiment is used, it should identify:

- the experiment being used;
- the rules being overridden;
- the expected benefits;
- the associated risks;
- the success criteria.

## Privacy Requirements

Do not submit:

- student records;
- student names;
- gradebooks;
- assignment submissions;
- protected educational records;
- personally identifying information.

All examples should be synthetic or anonymized unless explicit approval
exists and all applicable requirements are satisfied.

See REQUIRED/data_privacy.md.

## Style Guidelines

Prefer:

- reusable principles over one-time fixes;
- clear rationale over undocumented decisions;
- durable standards over temporary workarounds;
- evidence-informed recommendations over unsupported assertions;
- simplicity when functionality is equivalent.

When recommending a solution, consider:

1. Benefits
2. Drawbacks
3. Assumptions
4. Alternatives

## Scope

TeachingAI is intended to remain AI-independent.

Repository content should continue to be useful:

- without a specific AI product;
- across different instructional platforms;
- across different learning-management systems;
- across future AI systems.

Avoid changes that unnecessarily couple the framework to a specific
vendor, product, or model.

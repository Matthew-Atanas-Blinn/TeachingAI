# Decision: Repository Licensing

Status: Accepted

Date: 2026-10-30

Scope: Repository-wide

## Context

TeachingAI is primarily a repository of:

- educational standards;
- instructional practices;
- accessibility guidance;
- review procedures;
- governance documentation;
- decision records; and
- pedagogical rationale.

The repository is documentation-first rather than software-first.

The goals for licensing are:

- allow broad educational use;
- support adaptation and improvement;
- preserve attribution;
- prevent proprietary forks of the framework itself;
- encourage sharing of improvements; and
- remain compatible with public dissemination.

## Decision

TeachingAI is licensed under:

CC BY-SA 4.0

(Creative Commons Attribution-ShareAlike 4.0 International)

## Benefits

- Freely usable by educators.
- Freely adaptable.
- Commercial use permitted.
- Attribution required.
- Derivative works remain open.
- Supports collaborative ecosystem growth.
- Well understood within educational communities.

## Drawbacks

- Some organizations prefer more permissive licenses.
- ShareAlike may discourage some corporate adoption.
- Future code components may benefit from a different license.

## Alternatives Considered

### CC BY 4.0

Benefits:

- Simpler reuse.
- Maximum adoption.

Drawbacks:

- Improvements may become proprietary.

### MIT

Benefits:

- Extremely common.
- Highly permissive.

Drawbacks:

- Better suited for software than documentation.

### Proprietary Copyright

Benefits:

- Maximum control.

Drawbacks:

- Discourages collaboration and reuse.

## Assumptions

- The repository will remain documentation-focused.
- Educational reuse is a major objective.
- Open sharing of improvements is preferred over unrestricted proprietary reuse.

## Consequences

- Users may freely adapt TeachingAI.
- Attribution is required.
- Derivative repositories must remain under CC BY-SA 4.0.
- Future software tooling may eventually warrant separate licensing if the repository becomes heavily code-oriented.

## Revisit When

- Significant software tooling is added.
- The repository shifts from documentation-first to software-first.
- Licensing creates unexpected barriers to adoption.
